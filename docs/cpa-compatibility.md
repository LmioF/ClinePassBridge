# CPA 兼容性说明

ClinePassBridge 使用 JSON ABI v1，按 [README](../README.md#安装与配置) 安装到支持动态库插件的原版 CPA。插件功能以原版接口为边界，升级时备份插件目录、CPA 凭据目录与插件数据目录即可。

## 原版接口与提前截流

原版 CPA **v8.0.13** 已提供 `host.http.stream_close`，**v8.0.29** 也沿用该接口，插件可主动关闭上游流。「流式卡住时提前截流」从 v0.3.2 起提供，可在原版宿主上独立使用。

当前默认关闭，默认空闲阈值仍为 20 秒。首次安装或配置缺少字段时使用默认值；显式保存的 `true`、`false` 和自定义秒数在升级、重启后继续保留。开启后从首段有效输出后计时；思考、正文和工具增量重置计时，heartbeat、role 和空帧不重置，下游发送耗时不计入空闲时间。适用于上游 SSE 请求，包括非流式聚合；原生非流式不适用，也不缩短首字等待。Debug 另有独立开关，默认关闭，按需采集额外流诊断。配置见 [进阶配置](configuration.md#流式卡住时提前截流)。

统一错误规则使用原版 CPA 的 `request_scoped_errors`。已有凭据中的该字段继续保留；显式保存统一规则时按所保存规则更新。

## 错误状态与客户端重试

「重试兼容」默认开启，将已识别的指定 Fireworks/LiteLLM 响应截断规范为：

```text
HTTP 502: upstream response stream ended before completion: unexpected EOF (upstream_transport_incomplete)
```

插件按错误来源和结构化状态分类，对已归为请求范围的响应截断、闲置截流、网络/HTTP 回调失败、响应协议错误及上游 5xx，使用原版 CPA 的传输错误兼容路径，避免因本次故障新增账号/模型冷却。鉴权、402、429、套餐额度和团队限流优先保留原处置，包括被外层 502 包裹的明确受保护状态。该行为以插件实际分类和宿主识别为前提，不泛指所有 LiteLLM 错误或所有瞬时故障。

宿主冷却兼容与 `client_retry_compatibility` 开关独立。开启时规范上游服务/协议/连接错误，避免原始嵌套状态误导客户端；关闭时尽量保留原文，但宿主分类标签、生命周期文本和受保护错误摘要仍生效。原始诊断始终留在插件日志。

已核对的原版 CPA v8.0.13、v8.0.29 流错误接口只传字符串。插件对上述已分类的请求故障使用 EOF/timeout 识别词或明确的 `[clinepassbridge:cpa_compat:...]` 标签，并在对应 RPC 错误中省略内部 `http_status`（0 表示缺失）；下游由 CPA 默认封装为 500，已开始的 HTTP 200 通过 SSE error 结束，插件日志保留内部状态。此类 RPC 故障不再匹配自定义的 500/502 状态规则。兼容标签仅用于宿主分类，不表示已经确认底层断流原因。

本地响应/帧/前导大小超限单列为 `response_limit_exceeded`（413），保留 RPC 的 413 状态，并在错误文本中携带 `invalid_request_error` JSON，供已核对的宿主按请求错误停止同请求轮换并跳过本次新增冷却；它与上述省略 RPC 状态的兼容路径不同。应排查输出大小或配置上限。取消、截止时间和插件关闭也按请求生命周期处理。插件不自动重放已输出的内容，也不清除已有冷却。

CPA 可在首段输出前按自身请求重试预算重试；客户端也按自身配置决定重试。已核对的 DSH 源码 `d743267388641bc76f17c45ce8b4c231aed1d32c` 将规范文案归为可重试的 `SERVER`，实际受重试组件、策略和预算约束。插件不自动重放已开始的输出。

兼容性核对覆盖原版 CPA **v8.0.13、v8.0.29** 的 RPC、字符串流错误及冷却判定路径，并以受控故障样例验证；官方 v8.0.29 镜像也已完成插件加载检查。这些证据覆盖已测分类与调用路径，不代表所有瞬时故障均已在生产环境验证免冷却。插件同时针对 v8.0.29 新增的 HTTP/2 关闭识别词隔离受保护错误。

原版 CPA v8.0.13、v8.0.29 的插件链路不应用全局 payload 规则；插件安装与发布不依赖宿主定制。需要调整思考强度时，使用客户端参数或插件的思考强度映射。

## Token 计数

`/v1/messages/count_tokens` 当前由插件本地返回 HTTP 404，表示计数端点尚未实现。已核对的原版 CPA v8.0.13、v8.0.29 会将这类端点 404 记录为计数失败，但默认不因本次失败新增账号/模型冷却，普通生成仍可继续调度。该处理与「重试兼容」开关无关；已有冷却保留，显式配置的强制冷却规则仍按宿主规则生效。

此兼容处理尚未提供本地 token 估算或上游精确计数；实际用量继续使用生成响应中的 `usage`。

## 冷却与网络分类

请求仍计为失败，已有 CPA 冷却和团队退避保留；团队恢复探测遇已分类的请求/服务故障时只释放探测槽，不将其当成团队再次限流。其他宿主版本需重新核对错误识别与调度行为，实际冷却以 CPA 返回的状态为准。见 [调度说明](scheduling.md#响应截断与模型冷却)。

独立网络路径保留网络、取消和截止时间的错误类型；原版 HTTP 回调缺少类型信息时按回调来源记为 `upstream_callback_error`，不据此断言 DNS、TLS 等具体原因。文本回调仅在错误全文或结尾精确匹配 `context canceled` / `context deadline exceeded` 时识别为 499 / 504。已收到的鉴权、额度、限流 HTTP 状态优先于读取正文时的网络失败。完整诊断保留在日志；受保护错误原文若含宿主传输识别词，对宿主使用受控摘要，避免反向误豁免。

## 可选字段的被动兼容

运行实现保留对 `error_details`、`error_details_supported`、`model_states_available` 和 `model_states` 等可选字段的兼容读取。仅在宿主实际提供时使用这些信息，原版安装流程不依赖它们。

宿主未确认结构化流错误支持时，日志中的 `legacy_host_unknown` 仍表示处理结果未获宿主确认；文本识别兼容不提供这种确认，因此该值不代表兼容失效，也不应仅据识别词改记为已确认豁免。实际冷却以 CPA 状态为准。未提供模型范围时，账号卡片显示「调度受限」。
