# 调度、额度与代理出口

账号选择继续使用 CPA 的优先级、调度策略和会话黏性。插件负责 Cline 套餐额度判断、上游团队退避和可选的出口池。在「凭据管理」查看账号状态、用量、人工启停和清除冷却；在「模型映射」管理客户端名称与上游模型；在「代理池」配置出口和查看预算状态。

## 升级兼容

- 没有 `egress.json` 时出口池关闭，正式请求继续使用原来的 CPA HTTP 回调、全局代理和凭据代理。
- 通用出口池不依赖 Resin。支持 `http://`、`https://`、`socks5://`、`socks5h://`，以及显式的 `direct` 直连出口。
- 额度保护始终开启，额度耗尽后自动暂停，复查确认恢复后重新参与调度。旧配置中的 `quota_auto_pause: false` 按当前固定策略处理。`disabled` 仍然表示人工停用；自动额度状态单独保存。已有人工停用账号保持停用。
- 原有模型、API key、累计统计和其他 CPA 凭据元数据不会因本功能迁移而清空。
- 功能沿用原版 CPA 插件接口；原版 v8.0.13 已支持主动关闭上游流，提前截流可独立使用。已有凭据的 `request_scoped_errors` 继续保留，统一规则按显式保存的内容更新。错误状态与可选字段说明见 [CPA 兼容性说明](cpa-compatibility.md)。

## 响应截断与模型冷却

Fireworks/LiteLLM 的 `APIConnectionError` 中出现 `TransferEncodingError`、响应体未完成或传输长度不足时，插件按响应截断分类，保留上游 HTTP 状态与流内错误状态。异常文字里的 `400` 不会被当作请求的 HTTP 400。

已识别的指定 Fireworks/LiteLLM 响应截断，以及插件自己的闲置截流，不新建插件的团队退避窗口，也不触发额度暂停；已有退避继续保留。

对于已识别的响应截断与插件闲置截流，插件分别使用 `unexpected EOF` 和 `i/o timeout`，利用原版 CPA v8.0.13 的传输错误识别跳过本次新增账号/模型冷却。该行为覆盖流内错误、首段输出前的错误及非流式聚合，不依赖 CPA 补丁，也不清除已有冷却。首段输出前和非流式聚合通过 RPC 返回这两类故障时，插件省略内部 `http_status`（0 表示缺失），让 CPA 同样识别传输错误；下游默认按 500 封装，插件内部与日志仍保留 502。这两类故障不再匹配用户自定义的 500/502 错误规则；其他错误保留原状态和规则。

插件独立网络路径可按错误类型识别连接重置、DNS / TLS 失败、网络超时和提前 EOF，记为 `upstream_network_error`（502）；可识别的本地取消与截止时间分别记为 499 / 504。原版 CPA HTTP 回调只返回字符串，分类信息丢失，插件不从文字推断这些类别。真实上游 HTTP 错误保留原状态，即使读取错误正文时再次断网也保留。

上述请求仍以失败结束。CPA 可在首段输出前按自身配置重试；客户端也按自身配置、策略和预算重试。插件不重放已开始的输出或拼接第二次生成。已开始的 HTTP 200 保持原状态，以错误帧结束流。免新增冷却与「重试兼容」开关独立；关闭时仍保留宿主识别词。`legacy_host_unknown` 表示缺少宿主确认，实际冷却查看 CPA 状态。

卡片按 CPA 返回的信息显示账号调度状态和冷却，插件额度暂停单独显示。只有宿主提供模型范围时，才显示具体模型与恢复时间；仍有其他可用模型的账号不因单个模型冷却直接从可用总数扣除。未提供模型范围时显示「调度受限」。

## 额度耗尽

五小时、周或月任一窗口达到 100%，或上游明确返回 ClinePass 额度耗尽时，插件记录账号阻断状态并更新 CPA 的可用状态。已验证属于同一真实账号的多个 Key 共享该状态；账号名相同不会被当成同一账号。

重置时间只表示可以重新检查。后台取得新的成功用量结果、确认所有阻断窗口已恢复后，才重新参与调度。查询失败保留阻断。手动停用账号仍会被后台采样，也可在「凭据管理」手动刷新用量；额度恢复后继续保持人工停用状态。更换 API key 后，旧账号的自动额度状态失效。

用量接口存在采样间隔，因此请求开始时可能还未观察到最新的额度变化。实际额度耗尽响应会补充触发阻断。额度判断使用官方百分比，不使用页面估算的剩余金额。

## 通用出口池（实验性）

代理池默认关闭。建议先用一条代理和少量请求确认可用，再逐步增加出口。页面右上角的「使用指南」包含首次设置步骤、各字段解释和常见问题；需要恢复原有代理路径时，关闭「启用出口池」并保存即可。

添加出口时填写名称、代理地址、出口分组、每 60 秒请求数和最大在飞请求。认证地址示例仅用于说明格式：

```text
http://USER:PASSWORD@PROXY_HOST:PORT
socks5h://USER:PASSWORD@PROXY_HOST:PORT
direct
```

用户名、密码中的特殊字符需进行 URL 百分号编码。代理认证保存在插件数据目录的 `egress.json` 中，读取配置时脱敏；编辑已有出口留空代理地址，会保留原地址及认证。

同一个公网 IP 对应的多个代理地址应填写相同出口分组，并设置相同预算。不同用户名或代理端口不保证不同出口 IP。Resin 的黏性身份也适用这条规则：先确认实际可访问 Cline 的出口，再录入代理地址。节点健康、出口 IP 可用和模型实际可用是不同检查。

速率按滚动 60 秒管理，最大在飞数另行控制，流式请求持续占用在飞名额直到完成或关闭。账号已经指定的独立代理优先；否则从启用的出口中轮选。不因池耗尽或代理失败静默改走宿主直连。排队上限到达时返回本地限流。

未列入池的账号独立代理按代理网关地址共享保守预算（60 RPM、4 个在飞）；若要调整预算或按真实公网 IP 合并分组，应把相同代理地址录入出口池。池关闭时，独立代理的用量查询和管理探测仍可使用插件 HTTP 传输；普通推理继续沿用宿主传输。

预算属于当前插件实例。多个 CPA 实例共用同一公网 IP 时，需要拆分预算或使用外部集中限流，不能把每个实例的预算都当成该 IP 的独立额度。

## 本地 429 与真实上游 429

插件产生的本地额度、团队冷却或出口准入 429，会在完成判断和资源释放后直接返回，保留错误分类与重试信息。团队限流继续遵循上游重试时间和原有恢复探测逻辑；出口池在配置的排队时间内等待容量，超时后返回本地限流。

CPA 在进入插件前就可能因所有账号冷却而拒绝请求；这种请求由 CPA 原有调度逻辑处理，且不进入插件日志。出口传输保留请求超时、插件停止和流关闭时的取消与资源释放；出口池排队继续响应自身请求 context 的取消信号。

「清除冷却」清理插件退避并尝试调用宿主的冷却重置接口，不会增加上游额度。额度暂停或人工停用账号需先复查状态；宿主不支持操作时，页面会明确显示部分完成。

## 备份与回退

同时备份 CPA 的凭据目录和插件数据目录，包括 `settings.json`、`egress.json`。代理密码和凭据文件不要提交到公开仓库。关闭出口池会恢复原来的宿主代理路径。额度保护持续生效；「凭据管理」的启用开关管理人工状态，额度恢复时保留该状态。
